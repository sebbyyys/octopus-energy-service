# Implementation contract

Standalone UK Octopus REST data service. Python >=3.12, FastAPI, httpx, pydantic-settings, uvicorn; pytest, pytest-asyncio, pytest-cov, ruff, build for development. No GitHub configuration, remote, upload or publication permitted. Local Git initialization allowed, no commits needed.

## Shared representations
All datetimes timezone-aware, normalize stored strings to UTC ISO8601. Decimal calculations from strings; JSON output ordinary numeric floats. Period ranges [start,end). Dictionaries below are internal JSON-compatible representations.

Meter: `{id: 'electricity:<mpan>:<serial>' or 'gas:<mprn>:<serial>', fuel:'electricity'|'gas', meter_point:str, serial_number:str, is_export:bool, gas_unit:'kwh'|'m3'|'unknown', agreements:[{tariff_code:str, valid_from:str, valid_to:str|null}], active:bool}`. Discovery gas_unit defaults unknown; operator must explicitly configure gas units. Discovery skips properties already moved out; retains all meter serials, active true. E-2R pricing not silently treated as single-register.
Consumption: `{meter_id:str, interval_start:str, interval_end:str, consumption:number}`. Nonnegative finite consumption, positive interval duration. Consumption meter unit converted only in analytics, never storage.
Rate: `{meter_id:str, tariff_code:str, kind:'unit'|'standing', valid_from:str, valid_to:str|null, value_inc_vat:number, payment_method:str|null}`. Pence/kWh or pence/day. Select DIRECT_DEBIT or NON_DIRECT_DEBIT explicitly; null means applies to either. Filter agreement validity too. Negative unit rates supported. E-2R returned as unsupported by service unless implemented correctly.

## Client module src/octopus_service/client.py (client worker)
`OctopusClient(api_key:str='', *, transport:httpx.AsyncBaseTransport|None=None, timeout:float=20, retries:int=3)` async context manager, closes owned HTTP client.
`await client.account(account_number:str)->dict`
`await client.products()->list[dict]`
`await client.consumption(meter:dict,start:datetime,end:datetime)->list[dict]` normalized records as above.
`await client.rates(meter:dict,tariff_code:str,kind:str,start:datetime,end:datetime,payment_method:str='DIRECT_DEBIT')->list[dict]`
`discover_meters(account:dict)->list[dict]`; `product_code(tariff_code:str)->str` strict tariff parse.
`OctopusError` sanitized errors, `OctopusAuthError` subclass, `UnsupportedTariffError` subclass. HTTP Basic key username empty password only for private endpoints. Pagination enforce same https api.octopus.energy origin and allowed path (do not leak credentials), finite pages, detect cycles. Count check if count given. Retry network/429/5xx, not 401/403; bounded Retry-After. No secrets/raw response bodies in errors. Public endpoints usable without key. Tests use httpx.MockTransport; actual public API smoke test parent.

## Storage src/octopus_service/storage.py (analytics worker)
`Store(path:str)` opens SQLite, parent dirs, WAL, busy timeout, lock for thread use; `close()`.
`save_meters(meters:list[dict])`, `meters()->list[dict]` stable sorted.
`upsert_consumption(records:list[dict])->int`, `upsert_rates(records:list[dict])->int` idempotent identity and updates corrections.
`consumption(start:datetime,end:datetime,meter_id:str|None=None)->list[dict]` include overlapping intervals; optional meter filter.
`rates(start:datetime,end:datetime,meter_id:str|None=None)->list[dict]` include overlapping rates.
`set_meta(key:str,value:dict)` / `get_meta(key:str)->dict|None`; meta JSON, parameterized SQL, commits atomic per batch. Store data validates awareness/numerics. Store meter refresh marks stale removed meters inactive rather than silently destroying historical data, analysis only considers agreements.

## Analytics src/octopus_service/analytics.py (analytics worker)
`analyze(meters:list[dict], consumption:list[dict], rates:list[dict], start:datetime, end:datetime, *, timezone:str='Europe/London', payment_method:str='DIRECT_DEBIT', calorific_value:float=39.2, correction_factor:float=1.02264)->dict`
Result: `{period_from:str,period_to:str,currency:'GBP',timezone:str,totals:{import_kwh:number,export_kwh:number,gas_kwh:number|null,consumption_cost_gbp:number|null,standing_cost_gbp:number|null,export_credit_gbp:number|null,net_cost_gbp:number|null},daily:[{date:str,import_kwh:number,export_kwh:number,gas_kwh:number|null,consumption_cost_gbp:number|null,standing_cost_gbp:number|null,export_credit_gbp:number|null,net_cost_gbp:number|null}],habits:{hourly:[{hour:int,kwh:number,average_kwh:number}],weekday:[{weekday:int,kwh:number,average_kwh:number}],peak_hour:int|null,baseload_kw:number|null},quality:{complete:bool,missing_rate_intervals:int,unknown_gas_unit_meters:list[str],unsupported_tariffs:list[str],expected_intervals:int,observed_intervals:int,coverage_percent:number,warnings:list[str]},meter_totals:list[dict]}`
`meter_totals` entries at minimum `{meter_id:str,consumption_kwh:number|null}`.
Cost calculation splits readings over rate/agreement boundaries, proportional uniform energy approximation documented, electricity billing ROUND_HALF_EVEN each original interval to 0.01 kWh before split. Gas m3 * correction * CV / 3.6 estimated. Missing unit rate/unknown gas/Economy7 yields null affected cost, never fabricated zero. Standing per meter-point per local day once, no export standing charges, never double-count meter swaps; DST-aware days; proration for partial-day requests explicitly documented. All periods even days without readings present with quality warnings. Coverage reflect expected 30min intervals per unique active meter-point over agreement window; no multiply standing by serial count. Export credit subtract from import+gas costs. Include negative prices. Habits electricity import only, weekday/hour in local time, energy split across bucket boundaries, averages use calendar occurrences not reading count. Baseload estimate documented. Validation bounded parent service.

## Parent service
Settings env prefix OCTOPUS_, `.env` support. SERVICE_TOKEN mandatory min32. API_KEY/ACCOUNT_NUMBER optional together; blank both offline mode. DB_PATH ./data/octopus.sqlite3; TIMEZONE Europe/London, SYNC_INTERVAL_SECONDS >=300 default1800, INITIAL_DAYS default90 bounded1..730, LOOKBACK_DAYS7, PAYMENT_METHOD DIRECT_DEBIT, GAS_UNITS_JSON dict meter-id->kwh/m3, CALORIFIC_VALUE39.2, CORRECTION_FACTOR1.02264.
`create_app(settings=None, client_factory=None)` app factory. Public `/health/live`; all `/v1/*`, docs/OpenAPI protected Bearer token, disabled production docs acceptable. Routes GET `/v1/status`, `/v1/meters`, `/v1/consumption?start=&end=&meter_id=&limit=&offset=`, `/v1/rates` same, `/v1/analytics?start=&end=&meter_id=`, `/v1/home-assistant`, POST `/v1/sync` returns202 background job,409 busy,503 credentials absent. CSV `/v1/export?start=&end=&meter_id=` consumption rows. Query range max730d, aware datetimes, end>start, limits1..5000. Empty data null sensors rather than false zeros. Periods HA today,yesterday,week,month,previous_month. `/v1/home-assistant` JSON `{available:bool,stale:bool,last_sync:str|null,latest_reading:str|null,currency:'GBP',timezone:str,quality:dict, electricity:{total_kwh:number|null,today_kwh:number|null,yesterday_kwh:number|null,month_kwh:number|null,current_rate_pence:number|null},gas:{same},export:{total_kwh:number|null,today_kwh:number|null},cost:{today_gbp:number|null,yesterday_gbp:number|null,week_gbp:number|null,month_gbp:number|null,previous_month_gbp:number|null},habits:{peak_hour:int|null,baseload_kw:number|null}}`. Cumulative energy sensors measured from stored history (can be corrected), state_class total NOT total_increasing. Sensor costs estimates; not account balance/payments or live instantaneous power. Current rate fetched future rates during sync, not dependent on current consumption. Null unavailable semantics.
